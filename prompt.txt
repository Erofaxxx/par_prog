Основным заданием данной лабораторной работы является
разработка и исследование параллельных программ, созданных на
существующих
заготовок
последовательных
программ.
Полученные результаты требуется сравнить, а также изобразить
графически для каждой из реализаций зависимость коэффициента
ускорения программы от количества используемых исполнителей.
работа
подразумевает
выполнение
распараллеливания при помощи двух разных технологий (с общей
распределённой
памятью)
представленной
ниже
программы, а также дополнительно две или три, на усмотрение
преподавателя, индивидуальные задачи для каждого студента. Для
получения максимального балла требуется обеспечить возможность
установки ISIZE и JSIZE в значения 5000 и 5000 соответственно, для
чего, вероятно, потребуется модификация заготовки. Это желательно
для увеличения времени работы соответствующего фрагмента кода и
уменьшения влияния дискретности измерения времени на процесс
измерения эффективности параллельной версии программы. При
измерении времени требуется учитывать только время выполнения
заданного фрагмента кода, не учитывая время работы первого цикла
(который просто заполняет массив некоторыми данными и может быть
заменён другим источником данных), а также не учитывая время
записи данных в файл. Разрешается, по желанию студента, переписать
заготовку программы с использованием языка C++.

#include <stdio.h>

for (i=0; i<ISIZE; i++){for (j=0; j<JSIZE; j++){

}
//начало измерения времени
for (i=0; i<ISIZE; i++){

Приведённый выше вариант является эталонным в том смысле, что
является наиболее простым случаем для распараллеливания, в результате
чего следует ожидать максимальной эффективности распараллеливания
именно
для
данной
задачи
(при
условии
правильно
написанной
программы). Соответственно, эффективность работы индивидуальных
вариантов следует сравнивать с данным эталонным случаем.
Файл с результатами используется для проверки корректности работы
параллельной версии программы, для чего используется любая утилита
сравнения файлов (в ОС Linux чаще всего diff). Проверка корректности
работы параллельной программы является неотъемлемой частью процесса
разработки
параллельных
программ.
Проблематика
тестирования
параллельных программ достаточно обширна и выходит за рамки данной
лабораторной работы, в связи с чем предлагается воспользоваться
простейшим тестом в виде разового сравнения результатов.
